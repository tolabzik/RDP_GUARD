# RDP Guard 1.1.0-rc.2

Предварительный выпуск из `main`: Windows-пакет и Linux-агент для nginx stream /
Nginx Proxy Manager теперь устанавливаются готовыми пакетами и связываются одним
файлом `.rdpg`. Обычный RDP-клиент и внешний адрес подключения пользователей
сохраняются. Пароль root в панели не хранится.

**Прокси-интеграция работает в наблюдении. Автоблокировки Linux закрыты до проверки
целевой схемы (`enforcement_validated=false`).** Выпуск пакетов не означает, что
сквозная защита конкретного NPM/NAT/Windows уже принята.

## Файлы выпуска

- `RDPGuard-1.1.0-rc.2-win-x64.zip` и `.sha256` — Windows-приложение, службы,
  установщик, обновление и документация. Самостоятельно собирать EXE или ставить
  Python на Windows не требуется.
- `rdpguard-proxy_1.1.0-rc.2_amd64.deb` и `.sha256` — Ubuntu 24.04 amd64;
  Python-библиотеки приложения включены в пакет.
- `Install-ProxyRelease.sh` и `.sha256` — установщик именно этого выпуска. Проверяет систему,
  скачивает и проверяет пакет, устанавливает зависимости и открывает мастер.
- `INSTALL.md` — инструкция установки и подключения, отдельным файлом в релизе.

## Установка

**Сначала Windows:** скачайте ZIP и SHA256, проверьте хеш, распакуйте архив полностью.
В PowerShell от администратора из его папки выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Update.ps1"
```

Для новой установки используйте `Install.ps1`: он запросит имя и пароль
администратора панели. Обновление сохраняет учётную запись, настройки, списки,
историю и резервную копию; Windows-защита после обновления остаётся в Monitor Only.
Откройте **http://127.0.0.1:8787 → Прокси**.

**Затем Linux:** на Ubuntu 24.04 amd64 с NPM в Docker, в интерактивной SSH-консоли
с установленным `curl` выполните одну команду:

```bash
(set -e; rdp_installer=$(mktemp); trap 'rm -f "$rdp_installer"' EXIT; curl -fL --proto '=https' --tlsv1.2 'https://github.com/tolabzik/RDP_GUARD/releases/download/v1.1.0-rc.2/Install-ProxyRelease.sh' -o "$rdp_installer"; bash "$rdp_installer")
```

Мастер предлагает выбрать stream, адрес API и реальные IP администраторов,
показывает изменения NPM и после подтверждения создаёт `.rdpg`. Windows должен
достигать HTTPS-порта агента (по умолчанию `9443`); firewall мастер не открывает.
Оставьте мастер открытым и за 10 минут импортируйте файл на Windows через
**Прокси → Подключить файлом**. После привязки удалите переданную копию файла.

## Что изменилось

- Исправлена загрузка Linux-пакета из GitHub Release: имя файла теперь переносимое,
  `rdpguard-proxy_1.1.0-rc.2_amd64.deb`, без символа `~`, который GitHub заменяет
  при публикации. Ссылка установщика и имя в SHA256 совпадают с файлом выпуска.
  Внутренняя версия Debian-пакета — `1.1.0~rc2`.
- Linux сопоставляет Windows-события 131/140 с соединениями nginx и NAT, чтобы
  отделить реальный IP клиента от общего адреса прокси. Неоднозначные связи не
  становятся подтверждёнными клиентами.
- Привязка защищена одноразовым приглашением, закреплённым TLS-сертификатом и
  отдельным подтверждением сохранения данных Windows. Закрытый ключ клиента
  создаётся на Windows. После подключения постоянный обмен использует mTLS.
- Общий адрес прокси защищается от локального бана Windows; реальные доверенные
  адреса администраторов задаются отдельно на Linux.
- Пакет обнаруживает NPM/Docker и добавляет обратимый INFO include после
  `nginx -t`, с отдельной ротацией журнала. Генерируемые stream-файлы не редактируются.
- Новая установка `.deb` сама не запускает агент и не меняет nginx/firewall.
  Настройка запускается мастером; обновление сохраняет ключи, конфигурацию, базу
  и прежнее состояние службы. При существующей конфигурации helper не запускает
  новый мастер автоматически.
- Панель отдельно показывает связь, поступление событий и сопоставление адресов.
  Сохранённая привязка сама по себе не выдаётся за работоспособную защиту.
- Сохранены Windows-сборщик RdpCoreTS 140, отдельный подсчёт порогов источников,
  защита административных RDP-сессий, подтверждение переподключения и watchdog.

## Проверки и ограничения

Публикация GitHub Release зависит от тестов на Linux и Windows, сборки и нативной
проверки Windows-служб, установки/обновления/удаления `.deb`, а также проверки
обнаружения NPM, INFO-журнала, ротации и отката. Статус конкретного запуска виден
в [GitHub Actions](https://github.com/tolabzik/RDP_GUARD/actions/workflows/ci.yml).
[Предшествующий отчёт dev1](https://github.com/tolabzik/RDP_GUARD/blob/main/docs/PROXY_TEST_REPORT.md)
сохраняется как история проверки; он не заменяет результаты сборки этого тега.

Проверяемые платформы: **Windows Server 2022**, **Ubuntu 24.04 amd64**, **NPM 2.17.1**.
Server 2012 R2 для нового пакета пока не подтверждён. Поддерживается один IPv4 TCP
stream; UDP, IPv6 и дополнительный NAT с изменением peer IP/порта перед Windows
не входят в поддерживаемую схему. После пересоздания NPM нужно вручную проверить
и обновить привязку namespace; бесшовного восстановления пока нет.
