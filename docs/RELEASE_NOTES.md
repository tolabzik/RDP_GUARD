# RDP Guard 1.0.0-rc.8

Добавлено обнаружение отказов RDP через **RdpCoreTS/Operational, Event ID 140**. На Server 2012 R2 журнал Security может записывать неудачные NLA-входы как 4625/3 с `IpAddress=-`; такие записи не содержат адреса для блокировки. Новый сборщик читает IP из `IPString` отдельного события 140.

- Четвёртая подписка со своим bookmark и автоматическим восстановлением. Только штатный provider/канал и Event 140; события установления соединения не становятся отказами.
- События 140 с пригодным IP участвуют в блокировках автоматически, без включения общего Network-auth. Имя пользователя не угадывается по соседнему Security-событию.
- Порог считается отдельно по каждому журналу для одного IP за настроенное окно. Девять пар 4625+140 не достигают порога десять. Одному IP соответствует одно действующее решение, без двойной эскалации.
- Сохранены whitelist, защита активных администраторов, окно/сроки, Monitor Only, ограничение правил текущим RDP-портом, watchdog и подтверждение переподключения.
- Обзор показывает записи об отказах, включая записи без IP. Отдельная попытка может дать две записи. Уникальные IP считаются только по известным адресам. Счётчик за минуту перенесён из карточки доверенных сетей к отказам.
- У новых отказов без адреса явно указано «Нет IP для блокировки». Подписка RdpCoreTS видна в обзоре и диагностике; `health.failure_sources` показывает покрытие адресами по двум журналам за сутки.
- Добавлены 33 регрессии ядра. Локально: **192 passed**, 14 нативных Windows-проверок пропущены. Windows CI проверяет настоящие подписки на четыре канала и состояние всех сборщиков в установленном пакете до/после обновления.

**Обновление rc.1–rc.7:** распакуйте новый ZIP полностью и выполните из его папки в PowerShell от администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Update.ps1"
```

Создаётся резервная копия; учётная запись панели, настройки, списки и история сохраняются. Защита остаётся в Monitor Only. Проверьте новую подписку RdpCoreTS и появление 140 с IP, затем включите защиту, переподключитесь по RDP и подтвердите подключение в панели. Старые отказы вне текущего окна не вызывают новые баны; при стандартных настройках нужны 10 подходящих отказов **одного IP** за 300 секунд из одного журнала.

Event 140 не восстанавливает исходный адрес за обычным nginx stream: если Windows видит общий IP прокси, он остаётся общим для всех клиентов. Полная приёмка на Server 2012 R2 и фактическая блокировка внешнего RDP выполняются на целевом окружении; CI использует Windows Server 2022.

## Сохранённые исправления rc.7

Исправлен преждевременный откат в Monitor Only при RDP-переподключении. WTS может уже показывать новое соединение, когда последняя доступная запись LSM 21/25 ещё относится к предыдущему. Раньше первая неудачная сверка отменяла активацию, и панель отвечала `No pending activation`.

- Проверка повторно читает весь список WTS-сессий, токены и серверные события с общим бюджетом повторов 2 секунды и интервалом 100 мс. Успешная первая проверка выполняется без задержки.
- Каждая попытка заново проверяет Session ID, пользователя, административный токен, время и серверный IP. Старые записи и клиентский адрес за NAT не подставляются вместо нового доказательства.
- Если проверка остаётся неисправной, блокировки по-прежнему отключаются. Настроенный срок подтверждения активации не продлевается; подтверждение по истечении срока отклоняется и после повторных чтений.
- Добавлены девять регрессий задержанного LSM, смены сессии во время чтения, временно недоступного токена, постоянной ошибки, границ бюджета, whitelist и срока активации.

Исправления установщика из rc.6 сохранены:

Исправлена остановка установки на Windows Server 2012 R2 с ошибкой о совместном указании `RepetitionInterval` и `RepetitionDuration`.

- Задача `RDPGuardRollback` регистрируется через штатный XML Task Scheduler версии 1.2. Заданы запуск каждую минуту без срока окончания и запуск при загрузке, SID LocalSystem и повышенные права.
- Общий `WatchdogTask.ps1` используется и установкой, и обновлением. При обновлении отсутствующая задача восстанавливается до запуска служб; ошибка регистрации прерывает запуск.
- Windows CI проверяет фактическое повторное выполнение по таймеру и восстановление из состояния «службы остановлены, задача отсутствует» с сохранением учётной записи панели, whitelist и резервной копии.
- Добавлены ссылка на WMF 5.1 и инструкция восстановления после прерванной установки в `docs/OPERATIONS.md`.

Полная совместимость с Server 2012 R2 ещё требует проверки на целевой системе. CI использует Windows Server 2022; успешный запуск CLI на 2012 R2 не является проверкой всей защиты.

Исправления подтверждения переподключения из rc.5 сохранены:

- В rc.4 подтверждение требовало Security 4624/10 или 4778. Теперь используется LSM 21/25, уже проверенное по текущей активной административной RDP-сессии, пользователю/домену, Session ID и серверному IP.
- Время текущего подключения WTS должно быть после включения защиты; адрес должен оставаться в whitelist. Запоздалое событие старого подключения, чужой пользователь и истёкший deadline не подтверждают активацию.
- Отдельные 4624/7, 4624/10, 4778 или 1149 без привязки к новому подключению недостаточны. Классификация событий и правила блокировок не изменены.
- Подтверждение читает серверное событие напрямую через штатный Event Log API и не зависит от задержки сборщика SQLite. Принятые Session ID, IP и событие сохраняются в аудите.
- В диалог добавлена пошаговая инструкция переподключения; сообщение об отсутствии подтверждения переведено на русский.

Исправления NAT из rc.4 сохранены:

- IP административной сессии берётся из серверного события LocalSessionManager 21/25, а не из сообщённого клиентом WTSClientAddress.
- Сопоставляются активная сессия, административный токен, пользователь/домен и время текущего подключения из `WTSSessionInfoEx`. Старые события, другой пользователь и смена сессии во время проверки отклоняются. После переподключения источник проверяется заново.
- В `preflight` и панели отдельно показаны адрес на сервере (`ip`), справочный адрес клиента (`client_reported_ip`) и событие-источник (`ip_source`). Если проверка невозможна, возвращается причина `session_error`; fallback на неподтверждённый частный IP отсутствует.
- Добавлены регрессии NAT, смены адреса, повторного использования Session ID и подтверждения переподключения с прежним публичным whitelist. Логика классификации 4625 типа 3/10 не меняется.

Исправления rc.3 сохранены:

- Вместо сравнения английского имени `SYSTEM` проверяется SID учётной записи задачи. Локализованное имя `СИСТЕМА` разрешается штатным Windows API; принимается только LocalSystem `S-1-5-18`.
- Сохранены проверки действия задачи, успешного запуска и свежего heartbeat. При отказе `health` сообщает, какая проверка watchdog не прошла.
- Команда `rdpguard.exe preflight` и окно проверки перед ACTIVE показывают IP активных административных RDP-сессий и признак `whitelisted`. Просмотр не включает блокировки и не изменяет whitelist.
- Добавлены регрессии локализованных имён, отказа посторонним учётным записям, просроченного heartbeat и ошибок задачи; установленная сборка проверяет планировщик до и после обновления.

Исправления rc.2 сохранены:

- Обработан возвращаемый pywin32 код `ERROR_PIPE_CONNECTED`: клиент, подключившийся до вызова `ConnectNamedPipe`, обслуживается сразу. В rc.1 служба ожидала событие, которое не могло сработать.
- Добавлен ограниченный по времени повтор открытия занятого канала при конкуренции клиентов. Уже отправленные команды не повторяются.
- Добавлены нативная регрессия раннего подключения, 200 конкурентных обращений к Named Pipe и 100 параллельных запросов dashboard через установленные SYSTEM/LocalService службы с последующей проверкой CLI.

Возможности, сохранённые из rc.1:

- Python 3.12, две Windows-службы: SYSTEM Guard и непривилегированная LocalService Web.
- Event Log subscriptions/bookmarks, транзакционное SQLite WAL-хранилище, безопасная классификация 4625 типа 3/10.
- Порог/скользящее окно, временные блокировки и эскалация, whitelist/static blacklist, защита административных сессий.
- Только собственные TCP/UDP firewall-правила на RDP-порт с проверкой read-back; без драйверов, packet capture и изменений Kaspersky.
- Локальная панель с авторизацией Argon2id, CSRF и аудитом; шесть разделов, две темы, offline assets.
- Preflight, подтверждённое переподключение, независимая Scheduled Task rollback и emergency CLI.
- Установка/обновление/удаление, исходники, тесты и эксплуатационная документация.

Скачайте ZIP и соответствующий `.sha256`, проверьте хеш и распакуйте полностью. Запустите `Install.ps1` от администратора. Начальный режим **MONITOR ONLY**. Стандартных паролей нет. Python/Node/Docker на сервере не нужны.

**Это release candidate, не разрешение включать ACTIVE на рабочем сервере.** Сначала выполните `docs/ACCEPTANCE.md` на отдельной системе с резервной консолью. Проверка совместимости с Kaspersky 14.2, SQL Server и 1С требует целевого окружения. Известные ограничения описаны в `docs/LIMITATIONS.md`, включая отказ ACTIVE при отсутствии серверного доказательства адреса текущей административной сессии. Бинарники пока без Authenticode-подписи.

Аварийный откат: `C:\Program Files\RDPGuard\rdpguard.exe emergency-disable` из повышенной консоли, без веб-панели и основной службы.
