# RDP Guard 1.1.0-rc.3

Предварительный выпуск из `main`: **несколько Windows-серверов за одним nginx
stream / Nginx Proxy Manager**. Один Linux-пакет запускает независимые экземпляры
служб. Обычный RDP-клиент и внешние адреса пользователей сохраняются.

## Что изменилось

- `rdpguard-proxy add --instance accounting` добавляет отдельный stream с собственными
  сертификатами, HTTPS-портом, SQLite и областью блокировок nftables.
- Прежний узел остаётся `default` со службой `rdpguard-proxy.service`. Его настройки,
  ключи и разрешение enforcement сохраняются; новые узлы начинают в наблюдении.
- Добавлены `list`, `status --instance`, `doctor --instance` и адресное отключение
  `unconfigure --instance`. Дубли backend, stream ID, входного IP/порта и пересечения
  API/RDP-портов отклоняются.
- Общие INFO include и журнал NPM используются без повторного reload при добавлении
  второго узла. Ротация выполняется один раз на журнал и включена независимо от
  автозапуска агентов. Последний отключённый узел восстанавливает исходный include.
- Обновление `.deb` перезапускает только ранее работавшие экземпляры. Остановленные
  остаются остановленными; настройки автозапуска и данные сохраняются.
- Установщик релиза распознаёт и прежнюю конфигурацию, и установку только с
  именованными узлами; повторную привязку при обновлении не запускает.
- README и инструкция теперь содержат установку первого узла, обновление и
  добавление второго Windows. Протокол Windows совместим с `1.1.0-rc.2`.

## Обновить Linux

На Ubuntu 24.04 amd64 с NPM в Docker выполните в интерактивной SSH-консоли:

```bash
(set -e; rdp_installer=$(mktemp); trap 'rm -f "$rdp_installer"' EXIT; curl -fL --proto '=https' --tlsv1.2 'https://github.com/tolabzik/RDP_GUARD/releases/download/v1.1.0-rc.3/Install-ProxyRelease.sh' -o "$rdp_installer"; bash "$rdp_installer")
```

При первой установке откроется мастер. При обновлении сохраняются существующие
привязки. После обновления проверьте `sudo rdpguard-proxy doctor`.

Добавить второй узел:

```sh
sudo rdpguard-proxy add --instance accounting
```

Выберите свободный TCP stream, обеспечьте доступ нового Windows к отдельному
HTTPS-порту (обычно `9444`) и импортируйте его `.rdpg` в разделе «Прокси».

## Windows

Для новой установки скачайте ZIP, проверьте SHA256, распакуйте архив полностью и
выполните в PowerShell администратора `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Install.ps1"`.
Для обновления используйте `Update.ps1`. Настройки сохраняются; после обновления
локальная защита Windows остаётся в Monitor Only и требует повторной активации.
Для самого добавления нового Linux-экземпляра обновлять уже подключённый Windows
`1.1.0-rc.2` необязательно.

## Файлы выпуска

- `RDPGuard-1.1.0-rc.3-win-x64.zip` и `.sha256` — готовый Windows-пакет.
- `rdpguard-proxy_1.1.0-rc.3_amd64.deb` и `.sha256` — Ubuntu 24.04 amd64;
  версия внутри пакета `1.1.0~rc3`, зависимости Python включены.
- `Install-ProxyRelease.sh` и `.sha256` — установщик закреплённого релиза.
- `INSTALL.md` — первая установка, обновление и отключение.
- `PROXY_MULTI_INSTANCE.md` — добавление и обслуживание нескольких узлов.

## Проверки и ограничения

CI проверяет Linux/Windows, настоящие nftables, установку и обновление нескольких
systemd-экземпляров, NPM 2.17.1, общий журнал и восстановление после отключения.
Windows ZIP проверяется установкой служб на Windows Server 2022. Перед публикацией
файлы скачиваются из draft-релиза и сверяются побайтно и по SHA256.

Каждый узел обслуживает один IPv4 TCP stream и backend `IP:port`; до 32 узлов,
без обещания производительности на этом пределе. UDP/IPv6, изменение peer IP/порта
дополнительным NAT и автоматическая перепривязка после пересоздания NPM не добавлены.
Server 2012 R2 для нового пакета не подтверждён. NPM-стенд использует TCP echo,
поэтому проверка конкретного пути Windows/NAT остаётся отдельной.

Новая привязка получает `enforcement_validated=false` и начинает в monitor.
Разрешение блокировок первого узла не переносится на новые автоматически.
Уже сохранённое разрешение существующего Linux-узла при обновлении сохраняется.
