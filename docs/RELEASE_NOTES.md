# RDP Guard 1.1.0-rc.4

Автовосстановление после ночного выключения Windows, история причин остановок и
удобные списки клиентов прокси. Предварительный выпуск из `main`.

## Изменения

- После подтверждения ACTIVE сохраняется разрешение на автовосстановление.
  При перезапуске защита ждёт синхронизации времени и проверяет RDP, firewall,
  доверенный административный адрес, сторожевую задачу и журналы. Повторный вход
  пользователя после каждого планового выключения не требуется.
- Windows Time синхронизируется с уже настроенным источником. Ошибки времени
  и зависимостей видны в панели; повторные попытки выполняются автоматически.
- SCM повторяет перезапуски; независимый SYSTEM watchdog запускает остановленные
  службы. Веб-служба больше не зависит от работоспособности Guard и показывает
  страницу восстановления, пока основной процесс недоступен.
- «Система → История службы и восстановления»: старты, STOP, завершение Windows,
  исключения, повторные попытки и события SCM; экспорт JSON. Если причину
  невозможно установить, она отмечена как неизвестная.
- Linux заново определяет NPM и его PID namespace после перезапуска, проверяя
  прежний stream, backend, порт и каталог данных. Привязка и сертификаты сохраняются.
- «Прокси»: поиск по всей базе, статусы, сортировка, страницы по 50 IP, копирование,
  экспорт страницы и снятие выбранных банов. Доверенные сети Linux видны отдельно.

## Обновление

Сначала обновите Linux обычным установщиком этого релиза, затем распакуйте новый
Windows ZIP и выполните от администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Update.ps1"
```

После обновления **один раз включите ACTIVE, переподключитесь и подтвердите**.
Проверьте отметку «Автовосстановление разрешено». Привязка `.rdpg` не повторяется;
сохранённый режим прокси остаётся прежним. Для новых функций списков обновляются
обе стороны. Передача событий совместима с rc.3.

## Границы

Monitor Only и Emergency Disable отзывают разрешение автовосстановления. Ошибки
доступа, времени, неоднозначные события и изменённая привязка не обходятся.
Снятие выбранного бана не делает IP доверенным. Доверенные сети Linux в панели
пока доступны для чтения. Ограничения прокси IPv4/TCP и поддерживаемых ОС прежние.

Новые проверки включают переносимые сценарии ночного выключения/возврата
зависимостей и независимого watchdog, установку/остановку/аварийное завершение
на Windows CI и перезапуск настоящего контейнера NPM на Linux CI.
Реальный цикл «выключение вечером → включение утром» на вашей схеме требуется
проверить после установки; автоматические тесты его полностью не заменяют.
