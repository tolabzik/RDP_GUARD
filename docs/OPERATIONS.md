# Установка, конфигурация и обслуживание

Целевая ОС — Windows Server 2022 x64. Для панели нужен современный Edge/Chrome/Firefox в RDS. Приложение не требует входа пользователя для запуска служб.

## Каталоги и службы

- `C:\Program Files\RDPGuard\`: три exe и общая `_internal`. Не переносите отдельные exe без зависимостей.
- `C:\ProgramData\RDPGuard\`: SQLite, lease, emergency latch, защищённые журналы.
- `RDPGuardService`: LocalSystem, Automatic Delayed Start.
- `RDPGuardWeb`: LocalService, отдельный service SID, Automatic Delayed Start, зависит от Guard Service.
- `RDPGuardRollback`: SYSTEM Scheduled Task, раз в минуту и при загрузке.

Данные доступны SYSTEM и локальным администраторам. Веб-SID имеет только traverse родительского каталога и Modify в `web-logs`. Бинарники доступны для чтения/запуска Users, изменять их могут только администраторы и SYSTEM. SCM выполняет максимум два автоматических перезапуска подряд, затем оставляет службу остановленной до вмешательства.

## Аудит Windows

Для событий 4624/4625 должен быть включён системный аудит Logon success/failure. Проверяйте текущую политику, журнал Security и журналы TerminalServices. Установщик не меняет audit policy. При необходимости администратор отдельно выполняет после согласования:

```powershell
auditpol /get /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}"
# Только после решения администратора изменить системный аудит:
auditpol /set /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}" /success:enable /failure:enable
```

Сборщик использует подписку, отдельно сохраняет bookmark каждого канала, при временной ошибке переподписывается с экспоненциальной задержкой до 60 секунд. Не очищайте Security во время контрольного тестирования. Увеличьте его размер/retention по вашей политике, если событий много.

## Настройки

Параметры находятся в SQLite и изменяются в панели без перезапуска Windows. `defaults.json` описывает стартовые значения; это справочный файл, его редактирование не изменяет установленную службу. Режим защиты не устанавливается импортом JSON.

Первая блокировка 1 час, повторная 24 часа, третья и последующие 7 суток; последовательность `ban_seconds` можно настроить как возрастающую экспоненциальную. Автоматических постоянных блокировок нет. Порт Guard не изменяет Windows RDP. Смена порта допускается в Monitor Only с явным подтверждением и совпадением с реестром Windows.

Whitelist/blacklist импортируются JSON-массивами объектов `network`, `comment`. Импорт только добавляет записи, до 1000 за операцию; whitelist имеет приоритет и снимает всю пересекающуюся блокировку. Автоматические решения всегда относятся к одному адресу. История и счётчики нарушений сохраняются после снятия блокировки. Events очищаются по retention, аудит и история блокировок хранятся без автоматического удаления: следите за объёмом диска.

## Обновление

1. Скачайте новый release и проверьте SHA-256.
2. Запустите `Update.ps1` из нового архива в повышенной PowerShell.
3. Скрипт вызывает независимое emergency-disable, останавливает службы, сохраняет SQLite и бинарники в защищённый `backup-YYYYMMDD-HHMMSS`, заменяет программу и запускает службы.
4. Whitelist, blacklist, администраторы и настройки сохраняются. Защита остаётся выключенной до повторного preflight/активации.

При неудаче службы остаются остановленными, старые бинарники восстанавливаются. Если потребуется вернуть старую БД, сначала остановите обе службы, затем восстановите согласованный комплект `guard.db`, `guard.db-wal`, `guard.db-shm` из резервной копии. Не копируйте открытую SQLite обычным копированием файлов. Версия схемы проверяется; неподдерживаемая новая схема отклоняется.

## Удаление

`Uninstall.ps1` снимает собственные правила, удаляет две службы, задачу отката и каталог программы. Данные остаются. Для полного удаления данных используйте `Uninstall.ps1 -PurgeData` — это необратимо удаляет журналы, настройки и резервные копии. При ошибке emergency-cleanup программа не удаляет инструменты восстановления.

## Восстановление доступа

`rdpguard.exe reset-admin --username operator` в повышенной локальной консоли запрашивает новый пароль и отзывает сессии этого администратора. Пароли через аргументы командной строки не поддерживаются. `--password-stdin` предусмотрен для управляемой автоматизации, не передавайте секреты через shell history или журнал CI.

`Health.ps1`, System и `rdpguard.exe health` показывают состояние. Экспорт диагностики не включает пароли, хеши паролей, session tokens или CSRF, но содержит IP, имена учётных записей в аудите и административные комментарии: рассматривайте его как внутренние эксплуатационные данные.

С rc.3 `rdpguard.exe preflight` показывает все проверки перед ACTIVE, активные административные RDP-сессии и `whitelisted` для каждого IP. Команда только читает состояние. С rc.4 `sessions[].ip` — адрес из серверного LSM 21/25, связанного с текущим подключением через Session ID, пользователя/домен и WTS ConnectTime/LogonTime. `client_reported_ip` — справочный адрес клиента, который может быть частным за NAT; `ip_source` и `source_record_id` указывают доказательство. Если доказательство отсутствует, причина указана в `session_error`, ACTIVE запрещён. В панели те же данные доступны в окне проверки перед включением.

Для watchdog проверяется SID LocalSystem `S-1-5-18`, а не английское написание имени. `СИСТЕМА` на русской Windows является допустимым именем только если Windows разрешает его в этот SID. Путь/аргументы задачи, успешный запуск и heartbeat остаются обязательными; причины отказа указаны в `platform.errors` команды `health`.


С rc.5 подтверждение активации использует проверенное LSM 21/25 и время нового WTS-подключения после включения защиты. После активации закройте окно RDP на своём компьютере (не выходите из Windows), подключитесь снова под Windows-администратором с whitelist-адреса и нажмите «Подключение проверено» → «Подтвердить» до истечения 180 секунд. Обновление браузера не считается переподключением. Если произошёл автоматический откат, активацию и переподключение нужно повторить.

Последовательность 4624/7 + LSM 25 теперь принимается при совпадении текущей сессии, пользователя/домена, времени и серверного IP. Само событие 4624/7 означает разблокировку, а не доказанное RDP-подключение ([Microsoft](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4624)). При отказе проверьте `preflight`: `connected_at` должно быть после начала текущей активации, `ip` — текущий серверный источник, `whitelisted` — true. Новый адрес автоматически не добавляется. Данные принятого подтверждения сохраняются в аудите `activation-confirmed`.
