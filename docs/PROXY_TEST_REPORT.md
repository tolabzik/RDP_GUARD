# Проверка экспериментальной интеграции прокси

Версия ветки: `1.1.0.dev0`. Постоянный агент на рабочих серверах не развёрнут,
production firewall и маршруты не изменялись. При ранее разрешённой диагностике
временно включался INFO-журнал nginx; исходная конфигурация была восстановлена.
Эта запись не является разрешением production enforcement.

## Локальные результаты, 23 ноября 2026

- Полный pytest: **497 passed, 14 skipped** на macOS/Python 3.13. Пропущены
  проверки настоящих Windows API. Одна существующая deprecation-подсказка Starlette.
- Ruff, проверка whitespace diff, синтаксис JavaScript и shell-установщика проходят.
- Собран wheel `rdp_guard-1.1.0.dev0-py3-none-any.whl`; в нём присутствуют агент,
  сборщик, Windows worker, firewall planner, web assets и оба entry points.
- Настоящий локальный TLS: доверенный клиент принимается, чужой fingerprint и
  отсутствие клиентского сертификата отклоняются. Проверен общий срок HTTP-запроса.
- Панель и форма привязки открыты в браузере с искусственными данными; обмен
  с рабочим прокси при этой проверке отсутствовал.
- Сохранённые исходные XML реального диагностического окна проходят сверку:
  **101 событие, 40 сопоставленных соединений исследуемого прокси, issues=[]**.
  Коррелятор не включает исполнение правил. Пять отказов с другими native peer IP
  относятся к другому видимому пути и не считаются потерями данного прокси.
  Исходные пользовательские журналы и ключи в репозиторий не включены.

## Что покрывают регрессии

- Незавершённый netlink dump, backlog, ENOBUFS/разрыв журнала, смена namespace,
  устаревший checkpoint и начало новой ограниченной эпохи.
- XML/JSON provenance, host/stream/certificate binding, неполная история Windows,
  ограничение размера запроса, очереди и native XML.
- Повтор доставки, несовпадение native полей, неоднозначные поколения сокетов,
  невозможность повысить старые monitor-события до активных блокировок.
- Исключение общего IP из Windows-блокировок, в том числе ручных и импортируемых;
  исключение сохраняется при отключении обмена с агентом.
- TLS identity, авторизация панели и CSRF, свежая здоровая привязка для включения,
  новый контекст активации, снимки после reconnect/restart.
- Неизменность scope SQLite, атомарная запись решения и доказательства, whitelist,
  лимиты, явное снятие, применённые leases и незавершённое снятие.
- nftables planner/executor: конкретный destination IP, порт, TCP/явно разрешённый
  UDP; проверка владельца и структуры read-back; срок kernel lease не более 30 с;
  чужие таблицы и цепочки не изменяются.
- Bootstrap сертификатов: SAN/EKU/fingerprint, закрытые права файлов, отсутствие
  перезаписи существующего bundle и начальный monitor-only.

## Граница готовности

CI/портативные тесты не доказывают совместимость конкретной схемы NPM/Docker,
Windows 2012 R2, промежуточного NAT или происхождение ActivityID при намеренной
подмене клиентом. Нужна изолированная нативная приёмка, включая NAT с изменением
порта, конкурентные клиенты, отказ сборщика, перезапуск NPM, фактический packet path,
TTL и сохранение доступа доверенного пользователя. До неё
`enforcement_validated=false`; API не может менять этот локальный gate.

Установка, резервная копия и откат описаны в [PROXY_AGENT.md](PROXY_AGENT.md).
