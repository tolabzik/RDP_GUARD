Новые проверки dev1 охватывают:

- Одноразовую привязку с ограничением в 10 минут, проверкой CA, имени сервера и
  DER-отпечатка до передачи токена. Закрытый ключ Windows создаётся на Windows
  и не отправляется на Linux. Проверяются профиль сертификата, соответствие
  локальному ключу, компьютер и область привязки.

  Windows-сертификата и monitor-привязки. До ACK временный endpoint остаётся
  доступен в пределах срока приглашения. Отмена, истечение времени или неверный
  ответ не должны незаметно создать другую привязку или включить блокировки.
- Приватные каталоги и файлы ключей Windows, отказ от ссылок и небезопасных ACL,
  отсутствие токена в сохранённых файлах и аудитах. Проверка внутри собранной

  не включает службу; обновление восстанавливает только ранее работавшую службу,
  сохраняя настройки, сертификаты и SQLite. Удаление требует предварительного
  восстановления managed INFO include; remove/purge сохраняют пользовательские
  ключи и данные. Проверены реальные apt/dpkg/systemd на отдельном Ubuntu 24.04 runner.
- Обнаружение Docker publication и `/data`, проверку области stream, сохранение
  исходного custom include, `nginx -t`, обратимый reload и запись состояния
  восстановления до изменения файла. Конкурентные изменения оператора не
  перезаписываются.
- Отдельный INFO-журнал для TCP streams и его ротацию через собственный timer и

  Include общий для TCP streams выбранного NPM; правила блокировки по-прежнему

## Регрессии механизма сопоставления и блокировки

- Незавершённый netlink dump, backlog, ENOBUFS/разрыв журнала, смена namespace,
  устаревший checkpoint и начало новой ограниченной эпохи.
- XML/JSON provenance, host/stream/certificate binding, неполная история Windows,
  ограничение размера запроса, очереди и native XML.
- Повтор доставки, несовпадение native полей, неоднозначные поколения сокетов,
  невозможность повысить старые monitor-события до активных блокировок.
- Исключение общего IP из Windows-блокировок, в том числе ручных и импортируемых;
  исключение сохраняется при отключении обмена с агентом.
- TLS identity, авторизация панели и CSRF, свежая здоровая привязка для включения,
  новый контекст активации, снимки после reconnect/restart.
- Неизменность scope SQLite, атомарная запись решения и доказательства, whitelist,
  лимиты, явное снятие, применённые leases и незавершённое снятие.
- nftables planner/executor: конкретный destination IP, порт, TCP/явно разрешённый
  UDP; проверка владельца и структуры read-back; срок kernel lease не более 30 с;
  чужие таблицы и цепочки не изменяются.
- Bootstrap сертификатов: SAN/EKU/fingerprint, закрытые права файлов, отсутствие
  перезаписи существующего bundle и начальный monitor-only.

## Граница готовности

Первая версия мастера ограничена **Ubuntu 24.04 amd64**, одним **IPv4 TCP stream**
с конкретным IPv4 backend и одинаковым внешним/внутренним портом Docker.
Нативная Windows-проверка нацелена на **Windows Server 2022**. UDP, IPv6,
TLS-терминация на stream, несколько NPM replicas и дополнительный NAT,
меняющий peer IP/порт перед Windows, этим мастером не поддерживаются.

После перезапуска или пересоздания контейнера NPM может измениться PID namespace.
Сборщик не принимает новую область автоматически: `doctor` сообщает о несовпадении,
нужна ручная проверка и обновление привязки namespace с перезапуском агента.
Это ограничение текущей версии, а не обещание бесшовного восстановления.

CI/портативные тесты не доказывают совместимость конкретной схемы NPM/Docker,
Windows 2012 R2, промежуточного NAT или происхождение ActivityID при намеренной
подмене клиентом. Нужна изолированная нативная приёмка, включая NAT с изменением
порта, конкурентные клиенты, отказ сборщика, перезапуск NPM, фактический packet path,
TTL и сохранение доступа доверенного пользователя. До неё
`enforcement_validated=false`; API не может менять этот локальный gate.

Установка через пакет описана в [PROXY_SETUP.md](PROXY_SETUP.md), устройство агента,
резервная копия и откат — в [PROXY_AGENT.md](PROXY_AGENT.md).
