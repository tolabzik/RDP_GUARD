# Известные ограничения предварительного выпуска

- Проверки CI не заменяют контролируемую приёмку на реальном RDS-сервере с Kaspersky Endpoint Security 14.2, SQL Server и 1С. Эти продукты не установлены в GitHub runner. Production ACTIVE до такой проверки не считается принятым.
- IPv4/IPv6 событий и firewall поддерживаются. Для активной административной RDP-сессии WTS должен вернуть надёжный IPv4-адрес. При IPv6/неизвестном адресе администратора ACTIVE запрещается, поскольку текущий адаптер не имеет достаточно надёжного доказательства адреса. Явного whitelist самого по себе недостаточно для обхода этой проверки.
- Успех COM/read-back доказывает наличие собственных правил, но не доказывает блокировку пакетов всем сетевым стеком. Совместная работа с Kaspersky требует внешнего теста. Правила и настройки Kaspersky не читаются и не меняются.
- Preflight консервативно проверяет разрешающие правила с понятными адресами, портами и интерфейсами. Сложные GPO/IPsec/нестандартные interface scopes могут быть отклонены. Фактическая работоспособность RDP проверяется повторным подключением и внешней приёмкой.
- NLA-отказы нередко дают только LogonType 3. По умолчанию они видны, но не блокируются. Включение этой категории должно быть осознанным после проверки открытых служб.
- IP за NAT представляет несколько пользователей; успешная административная сессия защищает весь этот исходный IP. Система не различает пользователей за общим NAT.
- Истёкшие из журнала ОС события нельзя восстановить. На первом запуске читаются все доступные события выбранных каналов; старые записи не запускают блокировки. Большой накопленный журнал может увеличить время первичной синхронизации.
- Watchdog запускается раз в минуту: при аварии Guard Service снятие правил не мгновенно. Планировщик Windows и SYSTEM должны быть работоспособны. После перезагрузки с устаревшим heartbeat защита консервативно отключается, решения сохраняются для проверки.
- Аудит и история решений не удаляются автоматически. Ротация файлов логов ограничена 5 × 5 МБ на компонент; объём SQLite нужно контролировать.
- Дистрибутив x64, unsigned; MSI, автоматическое обновление и кластерная синхронизация не входят в RC1. Обновление выполняется скриптом с сохранением данных.
- HTTP предназначен только для 127.0.0.1, Secure-cookie не используется. Запрещено делать reverse proxy или публиковать панель в сеть. Пользователь с административным доступом к ОС вне модели угроз.
