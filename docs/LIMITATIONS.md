# Известные ограничения предварительного выпуска

- Проверки CI не заменяют контролируемую приёмку на реальном RDS-сервере с Kaspersky Endpoint Security 14.2, SQL Server и 1С. Эти продукты не установлены в GitHub runner. Production ACTIVE до такой проверки не считается принятым.
- IPv4/IPv6 событий и firewall поддерживаются. С rc.4 адрес административной сессии подтверждается серверным событием LSM 21/25 с теми же Session ID, пользователем/доменом и временем текущего подключения WTS. Если событие удалено, содержит LOCAL/неизвестный IP, относится к старому подключению или время WTS недоступно, ACTIVE запрещается. После очистки LSM может потребоваться новое RDP-переподключение, чтобы Windows записала источник. Явного whitelist самого по себе недостаточно для обхода этой проверки.
- WTSClientAddress сообщает адрес со слов RDP-клиента: при NAT/VPN он может отличаться от адреса соединения. В rc.4 он показан только как `client_reported_ip` и не используется для whitelist или firewall. См. [ограничения WTS_CLIENT_ADDRESS](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ns-wtsapi32-wts_client_address). Для RD Gateway и других схем, где сервер не записывает проверяемый адрес текущей сессии, режим остаётся Monitor Only.
- Успех COM/read-back доказывает наличие собственных правил, но не доказывает блокировку пакетов всем сетевым стеком. Совместная работа с Kaspersky требует внешнего теста. Правила и настройки Kaspersky не читаются и не меняются.
- Preflight консервативно проверяет разрешающие правила с понятными адресами, портами и интерфейсами. Сложные GPO/IPsec/нестандартные interface scopes могут быть отклонены. Фактическая работоспособность RDP проверяется повторным подключением и внешней приёмкой.
- Security 4625 с LogonType 3 по умолчанию видны, но не блокируются. Включение этой категории должно быть осознанным после проверки открытых служб. С rc.8 отдельные RdpCoreTS 140 с пригодным IP учитываются автоматически как отказы RDP, независимо от настройки типа 3.
- Событие 4625 без пригодного адреса источника (`IpAddress` пустое, `-` или защищённый локальный адрес) сохраняется в журнале, но не создаёт IP-блокировку. Наличие Hyper-V/NAT само по себе не доказывает причину отсутствия адреса. Корреляция по одному времени с чужими сетевыми соединениями не используется.
- С rc.8 используется дополнительный источник RdpCoreTS/Operational 140 с `IPString`. Если канал отключён или Windows не создаёт 140 с IP, адрес восстановить невозможно. Служба не включает журналы и не меняет аудит сама. Порог считается отдельно по Security и RdpCoreTS, чтобы дубли из двух журналов не ускоряли бан. Обзор считает записи, а не уникальные попытки.
- IP за NAT представляет несколько пользователей; успешная административная сессия защищает весь этот исходный IP. Система не различает пользователей за общим NAT.
- Обычный nginx stream/Nginx Proxy Manager открывает соединение к Windows со своего адреса. Event 140 не восстанавливает реальный IP за таким прокси: блокировка общего адреса затронет всех клиентов, а whitelist исключит из блокировок весь этот поток. Для различения источников нужна архитектура с сохранением IP или отдельное достоверное сопоставление и блокировка на границе; это не входит в rc.8.
- Истёкшие из журнала ОС события нельзя восстановить. На первом запуске читаются все доступные события выбранных каналов; старые записи не запускают блокировки. Большой накопленный журнал может увеличить время первичной синхронизации.
- Watchdog запускается раз в минуту: при аварии Guard Service снятие правил не мгновенно. Планировщик Windows и SYSTEM должны быть работоспособны. После перезагрузки с устаревшим heartbeat защита консервативно отключается, решения сохраняются для проверки.
- Аудит и история решений не удаляются автоматически. Ротация файлов логов ограничена 5 × 5 МБ на компонент; объём SQLite нужно контролировать.
- Дистрибутив x64, unsigned; MSI, автоматическое обновление и кластерная синхронизация не входят в RC1. Обновление выполняется скриптом с сохранением данных.
- HTTP предназначен только для 127.0.0.1, Secure-cookie не используется. Запрещено делать reverse proxy или публиковать панель в сеть. Пользователь с административным доступом к ОС вне модели угроз.
